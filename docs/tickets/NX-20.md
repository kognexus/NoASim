# NX-20: Interactive web demo

See [PLAN.md](../PLAN.md) for the behaviours (B*) and hypotheses (H*) referenced here.

## Acceptance criteria

- [x] Twin arms side by side with the same disturbance
- [x] Mode selector
- [x] Model selector (Nominal / RLS / PHNN)
- [x] Impact-policy selector and brake toggles
- [x] ACK button
- [x] Latency, jitter and drop sliders
- [x] Click a joint to inject ripple, shaker, tap, impact or bearing fault (partly: see log)
- [x] Arm editor (partly: see log)
- [x] Live plots
- [x] Bus view with message flow and event log
- [x] E-STOP and reset

## Tests

- `web/src/rig.test.ts` (the demo's simulation side, headless):
  - both arms get a tap at the same cycle, and the networked arm's mean tool distance over
    the next half second is under 0.6× joint control's, with no impact reaction while
    reaction is off;
  - torque ripple in joint 3 during a figure of eight is claimed by joint 3, and only
    joint 3, on both arms;
  - a collision with reaction on makes both arms report the impact; E-STOP removes the
    drive torque.
- `npm run build -w web` builds the page.

## Log

- 2026-10-21: `npm run dev -w web`. Two KX-6L arms side by side, each drawn with three.js
  straight from its MuJoCo model (every geom's pose copied from the simulation each
  frame). Joints are discs on their axes, coloured by the status the joint reports on
  the bus: ready, network damping, holding, fault, torque off.
  - **Per arm:** damping mode (joint control only, joint-local, network, network + report
    to source) and model (datasheet, fitted RLS, learned PHNN), switched live through the
    settings frame. Both damping laws are carried with their tuned gains, so switching
    needs no rebuild.
  - **Shared:** task (hold, pick and place, figure of eight, both through joint-level
    interpolation); tap, shake and collide at the tool; select a joint by clicking it and
    give it a fixable (10 % of rated) or unfixable (50 %, beyond the compensation budget)
    torque ripple at the sixth electrical harmonic; clear faults; impact policy, "react to
    impacts", ACK, E-STOP (the hardwired STO line), reset; bus latency, jitter and frame
    loss applied live (new `EthercatBus.configure`).
  - **Arm editor:** stiff KX-6 or lightweight KX-6L, payload 0–3 kg, link bending stiffness
    25–200 %, brakes. Actuators as on the datasheet, or a committed unit's hidden actuators
    with its learned models (KX-6 only, as the models were trained on KX-6 units).
  - **Live views:** tool distance from where it should be (both arms, last 5 s); the bus of
    either arm as a line of nodes with pulses for non-cyclic frames, frames per second by
    kind, and an event log of impacts, faults and disturbance claims.
- Tapping is a collision as far as the joints can tell (200 N at the tool), so with
  impact reaction on, a tap stops the arm. Reaction is therefore off by default and the
  Collide button turns it on.
- The fixable ripple is at the sixth electrical harmonic, not the gear mesh. At the
  speeds of the demo tasks the mesh order is mostly below the band where attribution
  works, so a mesh ripple would rarely be named.
- On the lightweight arm the source's own claim never came: its residual's RMS, which the
  coherence test compared against, is dominated by link vibration far from the order.
  The self-test now compares the order's amplitude with a lock-in reference beside it
  (NX-15).
- Not done: an editor for the number of joints or link lengths (the arm body is chosen
  from the two specs). Tap, shake and collide act at the tool rather than at a clicked
  joint. The "bearing fault" is the unfixable ripple (NX-12 found that a bearing defect is
  incoherent, so nothing in the arm can attribute it).
- Speed: two arms step at about 2.2× real time in Node; the page steps for at most 14 ms
  per frame and shows the real-time factor. A browser tab that is hidden stops animation
  frames, and with them the simulation.
