# NX-06: Bus + discovery (B0)

See [PLAN.md](../PLAN.md) for the behaviours (B*) and hypotheses (H*) referenced here.

## Acceptance criteria

- [x] 4 kHz cycles, distributed clock, latency, jitter and drops, byte budget
- [x] Nodes announce capabilities (brake, model version)
- [x] 6 nodes discovered in a bounded number of cycles
- [x] Hot unplug detected

## Tests

- `sim/src/bus/ethercatBus.test.ts`: delivery no earlier than the latency, neighbour
  routing (two neighbours + host), unicast by assigned address, drop rate, jitter never
  reorders a link, cut cable
- `sim/src/harness/discovery.test.ts`: all six nodes READY within 4·latency + 4 cycles
  (latency 1 and 3), byte budget never exceeded, unplugged nodes reported lost within
  the watchdog, arm held during start-up
- `crates/nexus-node/src/neighbours.rs`: neighbour table keeps adjacent nodes and only
  their newest state

## Log

- 2026-10-21: `EthercatBus` relays frames by destination byte (host, node, neighbours,
  all) with at least one cycle of delay, optional jitter (without reordering a link),
  seeded frame loss, a cable cut, and byte accounting with 12 bytes of datagram overhead
  per frame.
- Discovery (host): count reachable nodes, assign address = line position, collect
  announcements, send limits, done when all are READY; then a watchdog. Measured: READY
  at cycle 4 with 1-cycle latency, cycle 12 with 3-cycle latency.
- Each node keeps a table of its inner and outer neighbour (announced parameters, latest
  state, its age), which neighbour damping and gravity use later.
- Bus load with six nodes publishing every cycle: peak 936 of 3125 bytes per cycle (30 %).
- New composition root `ArmSystem` (plant + actuator physics + sensors + nodes + bus +
  host, one 4 kHz cycle per `step`). With only the PD hold, the arm sags about 3 cm under
  gravity at the tool. Gravity compensation comes in NX-08.
