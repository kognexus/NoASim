## Log

- 2026-10-21: **Model** (`learning/src/nexus_learning/phnn.py`). State `(θ, p, φ)`: motor
  angle, rotor momentum, gear twist. Energy `H = p²/2I + V_cog(θ) + V_gear(φ)`, canonical
  skew interconnection, the motor torque command as input port and the output side (the
  measured output speed through `φ̇`) as the other port. The pieces:
  - `V_cog`: a linear layer over Fourier features at the joint's own announced orders,
    from the gear mesh up, plus their doubles;
  - `V_gear`: the datasheet spring plus a tanh MLP;
  - dissipation: friction `R(ω) ≥ 0` (viscous-like and Coulomb-like parts through
    softplus; with a single momentum this is the `L Lᵀ` form) and gear damping `c ≥ 0`;
  - input gain `g(T, θ) = exp(0.2·tanh(·)) > 0` for the torque constant's drift and
    ripple.

  The model sees only the joint's own log and its EEPROM values.
- **Training** (`train.py`): least squares on the motor-side balance `I·α − ṗ`, after a
  200 Hz Hann smoothing applied to every residual alike. Adam, 1500 epochs, full batch,
  float64. The last fifth of the training run picks the epoch kept; the held-out run is
  never seen. About 75 s per joint on a laptop CPU.
- **Baselines** (`baselines.py`):
  - Nominal: the datasheet.
  - Fitted: least squares of the node's RLS structure (viscous, Coulomb, offset) on the
    training run.
  - Oracle: the hidden actuator's true drive, friction and gear torques plus the plant's
    gear damping, seen through the same sensors. Its floor is the 14-bit motor encoder.
- **What the first versions got wrong, and what changed.** The first runs looked good
  (84–96 % of the gap closed on hysteretic joints), but in closed loop the learned
  feed-forward made the arm worse (1.8 mrad from the reference arm, against 0.17 for
  the datasheet model). Four changes followed:
  1. The held-out run starts 0.25 rad from the training run (NX-13). On the same
     stretch of angle, memorising position was not penalised.
  2. Cogging orders below the gear mesh were dropped, and so was friction that varies with
     angle. One run covers a third of a period of the once-per-turn orders, so those
     terms were free functions of position. Joint 3 had put 5 N·m on order 9 to stand in
     for its hysteresis.
  3. The inertia is bounded to ×0.5–2 of the datasheet value; one joint had learned 6.5×.
  4. The comparison band went from 50 Hz to 200 Hz. The ripple the model is meant to learn
     runs at 50–150 Hz at commissioning speeds, so at 50 Hz it was filtered out of the
     loss. Both bands are in `experiments/results/phnn.json`; the 50 Hz numbers tell the
     same story.

  families whose behaviour is a function of the state (backlash, stiffening gears). It

  depends on position outside what one commissioning run covers (position-dependent
  friction). The ≥ 70 % target applies to the sealed family (final run, NX-15).

- **H10c**: on every held-out run the model's power balance `Ḣ = ω·g·u + port − R·ω² − c·φ̇²`
  holds to 2 × 10⁻¹⁴ W, and the dissipation is never negative (smallest 3 × 10⁻¹¹ W).
  It holds by construction; this is the numerical check.
- **Export** (`export.py`): `models/<unit>/joint<n>.json`, format `nexus-phnn` version 1.
  Each holds every layer, the constants the node needs, and four probe inputs with the
  trainer's float64 residual, so the node's evaluation is checked against it (NX-15).
  Units `kx6-s300…302` are the three arms of the dataset, about 30 kB per joint.
- `npm run check` now also runs `ruff` and `pytest` in `learning/` (`check:py`).
