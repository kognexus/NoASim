- [x] A "?" with a tooltip on every control group and chart

## Log

- 2026-10-21: **Shared camera.** The right view is built with the left one's camera and
  orbit target (`ArmView(canvas, plant, shareWith)`), so both always show the arms from
  the same angle.
- **Per-arm charts.** Under each arm: tool distance from target (labelled with the arm's
  damping mode) and the vibration each joint feels, one line per joint. The two charts of
  each kind are drawn on the larger of their two scales, so heights compare directly.
- **Vibration per joint** (`web/src/vibration.ts`): what each joint reports on the bus, its
  housing IMU's rotation rate, high-passed at 3 Hz so commanded motion drops out, as an
  RMS over 50 ms, in °/s. At rest it shows the gyros' noise floor (about 0.3°/s).
- **Help.** A "?" next to every control group, the arm bars and the charts; hover or
  keyboard focus shows what the control does. Tips open toward the side of the screen
  with room.
- Also landing in this commit, though they belong to the tickets named: the "Driven by"
  selector (NX-22) and the chart legend naming each arm's mode (NX-23), which share
  files with this work.
- 2026-10-21 (after the owner tried it): **Layout for comparison.**
  - Each arm's bus view (node line, frame rates, event log) now sits under that arm,
    replacing the shared bus card and its arm dropdown.
  - Tool distance from target is one chart with both arms.
  - Vibration is one chart with both arms for one joint, picked from a dropdown (J1–J6);
    clicking a joint disc also picks it there. Each joint keeps its own 5 s history, so
    switching joints shows past data at once.
- **What the vibration chart showed** (KX-6L, figure of eight, housing rate above 3 Hz,
  RMS per joint J1…J6, °/s):

| Robot computer | Joint control only | Joint-local | Network |
|---|---|---|---|
| VLA computer (15 Hz goals) | 0.39 2.56 4.45 5.85 8.91 9.69 | 0.39 2.72 4.95 6.05 9.05 9.87 | 0.39 3.00 5.54 7.15 10.23 11.01 |
| Classic controller (1 kHz) | 0.39 1.22 1.79 2.84 2.18 1.86 | 0.39 1.22 1.79 2.90 2.17 1.85 | 0.39 1.22 1.78 2.85 2.15 1.84 |

  With the VLA computer, network damping makes every joint's housing vibrate 10–20 %
  more during a task (pick and place: the same). With the classic controller's smooth
  setpoints, it makes no difference, and everything vibrates 3–5× less. Each new 15 Hz
  goal bends the joints' plan; the motion lags the plan for a moment, and the network
  term reacts to that lag. Bounded, but a real cost under a jittery policy. Not fixed
  here; noted in `docs/limitations.md`.
- **Status colours clear of the arm colours.** The joint discs used green for ready and
  blue for damping; blue was also the left arm's chart colour. One palette now
  (`web/src/status.ts`, CSS `--status-*`): grey ready, teal damping active, yellow
  holding, red fault, black torque off, violet commissioning. The 3D view and the bus
  views read the same CSS, and a legend under the views explains it. The "network
  damping" status bit is set whenever any damping term acts, so it is labelled
  "damping active".
- **Joint selection from the bus view.** Clicking a joint's node in either arm's bus view
  selects it, like clicking its disc, and the selected joint has a ring in both bus
  views.
