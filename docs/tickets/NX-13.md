# NX-13: Commissioning run + dataset (B11)

See [PLAN.md](../PLAN.md) for the behaviours (B*) and hypotheses (H*) referenced here.

## Acceptance criteria

- [x] Each joint runs its own excitation inside its limits
- [x] Logs exported per joint with train / held-out split
- [x] Deterministic per seed

## Tests

- `crates/nexus-node/src/excitation.rs`: the excitation stays within its excursion and
  speed budget, keeps clear of a near position limit, starts and ends at rest without a
  jump, and differs between seeds
- `crates/nexus-proto/tests/golden.rs`, `sim/src/bus/protocol.test.ts`: the `Commission`
  frame, byte for byte in both codecs
- `sim/src/harness/commissioning.test.ts`: on hidden actuators only the commissioned joint
  moves (others < 10 mrad), within 0.4 rad and 1.6 rad/s, with no fault, and it comes back
  to its start; the log is identical for the same seed, different for another, and has
  ground truth for every logged cycle

## Log

- 2026-10-21: **Wire.** A `Commission` frame (kind 13: duration in cycles, seed) asks one
  node to excite itself; the node sets `COMMISSIONING` in its status while it runs. It
  ignores goals during the run and holds its start angle afterwards. An impact or comm-loss
  reaction ends it.
- **Excitation** (`excitation.rs`): a multisine of 8 components, log-spaced 0.2–6 Hz,
  with amplitude ∝ 1/√f (between equal position and equal speed per component). Phases
  are Schroeder's, perturbed by the seed. It is scaled to the tighter of ±0.35 rad
  (and 0.1 rad clear of the position limits) and half the speed limit, counting the
  1 s sin² fade-in and fade-out. The joint's own controller follows it; the
  others hold, so the log shows the joint working against the arm's real load.
- **Dataset** (`experiments/src/commission.ts`, `sim/src/scenarios/commissioning.ts`):
  per arm seed, each KX-6 joint on hidden actuators (open families) runs 10 s for training
  and 5 s, with another seed, held out.
  - The joint's log is what it publishes on the bus every cycle: motor and output angle
    and velocity, gear twist, current, commanded torque, temperature.
  - `meta.json` holds what each node knows about itself (its EEPROM values and
    fingerprint) and the timing convention: a command acts one cycle later.
  - Ground truth (the actuator's drive, friction and extra gear torque, and the true state)
    goes to a separate `truth/` folder with the drawn families. Only the Oracle baseline
    and the evaluation read it.
  - Three arm seeds give 18 joints covering all five open families: `kx6-s300`
    `stribeck-position, ripple-thermal, hysteretic-stiffening, textbook, stribeck-position,
    hysteretic-stiffening`; `kx6-s301` `ripple-thermal, stribeck-position, ripple-thermal,
    hysteretic-stiffening, hysteretic-stiffening, backlash`; `kx6-s302` `stribeck-position,
    textbook, hysteretic-stiffening, stribeck-position, textbook, backlash`. About 64 MB per
    seed, regenerated in about 70 s, not committed.
- `--sealed` writes a dataset of the sealed family. It has not been run; it is reserved
  for the final H10 run (NX-15).
- Observed: after a run on hidden actuators the joint settles up to ≈ 20 mrad from its
  start. This is the static error of a PD with nominal friction feed-forward on unknown
  friction, which is exactly what the learned model should fix.
- `withArm` in the experiment runner now awaits asynchronous runs before disposing the arm.
