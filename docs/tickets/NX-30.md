# NX-30: Estimator-based coordinated damping

See [PLAN.md](../PLAN.md) for the behaviours (B*) and hypotheses (H*) referenced here.
NX-29 found that a damping gain seeing two joints either side matches the ideal
controller on the true state, but run as a static gain on the joints' bus data it
oscillates: its model treated the measurements as clean, delayed states. Asked for by
the owner: estimate the state with filters that model what is between the plant and the
gain, and design on that model.

## Acceptance criteria

- [ ] The linear model checked against the simulation before it is designed on: tap
  responses with damping off compared, and every known gap closed or named
- [ ] A model with what NX-29 left out: bus latency on other joints' data, the cycle of
  actuation delay of the joints' torque, gyro bias; measurements only what is raw in the
  joints' frames (encoder angles, gyros)
- [ ] A Kalman filter on that model and a gain designed on it; evaluated in simulation
  on bus data only: taps at the pose designed for and at another, both arms
- [ ] Each joint's filter restricted to the joints up to two places away, if the full
  one holds up; in the node if that holds up, inside the energy tank and torque cap
- [ ] Measured against network damping wherever it is built: taps, tasks, bus faults
