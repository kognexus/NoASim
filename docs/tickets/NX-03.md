# NX-03: Sensor models

See [PLAN.md](../PLAN.md) for the behaviours (B*) and hypotheses (H*) referenced here.

## Acceptance criteria

- [x] Dual absolute encoders (quantised), Hall sectors, IMU (noise, bias, bandwidth), current, lumped thermal model
- [x] Tests check noise statistics

## Tests

- `sim/src/sensors/models.test.ts`: encoder resolution and error statistics, Hall sector
  sequence, IMU noise vs density × √(π/2·f_c) for gyro and accelerometer, per-unit bias,
  clipping, current noise, temperature lag, `JointSensors` reproducibility and accuracy
- `sim/src/plant/thermal.test.ts`: thermal steady state, ideal drive torque/current, every
  KX-6 joint stays below its winding limit at rated torque
- `sim/src/util/random.test.ts`: seeded streams are reproducible and independent

## Log

- 2026-10-21: Sensor models for the Nexus unit (`sim/src/sensors/`) with parameters in
  `NEXUS_SENSORS`: 14-bit motor-shaft encoder (9× finer at the output), 19-bit output
  encoder, Hall sectors, BMI330-class IMU (bias, bias walk, white noise, 750 Hz filter,
  range, 16-bit word), 12-bit current sensing with offset, lagging NTC. Physics and
  measurement are kept apart: `IdealDrive` and `ThermalModel` (plant side) produce the
  true current and winding temperature; the sensors only measure.
- Added electrical and thermal data to `ActuatorSpec`. KX-6 values follow the motor study
  (30/32 SPM, 0.316 N·m/A). The thermal networks were retuned so that rated torque is
  truly continuous (110–115 °C steady state against a 130 °C limit).
- Seeded `Random` (xoshiro128**) with per-sensor derived streams, so `prove` runs are
  reproducible and adding a sensor does not change another sensor's noise.
- Encoders report a continuous (multi-turn) angle; turn counting is assumed to happen in
  the encoder or firmware.
